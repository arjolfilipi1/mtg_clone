What the current design does
Each Card node owns a CardHighlightManager child. That child manages:

Hover state — tracking if the mouse is over the card or its buttons
Scale tween — animating the card's scale up/down on hover
UI_Manager.highlighted — setting/clearing the global "which card is hovered" reference
A debounce timer — so moving from card to button doesn't flicker

The reason it's per-card is that the tween and hover state are naturally local to each card. The problem is cost — N cards = N nodes, N tweens potentially allocated, N sets of signal connections.

The migration plan
Step 1 — Move hover detection to UI_Manager, keep tweens lightweight
UI_Manager already has all_board_nodes and highlighted. The cleanest approach is to handle hover events centrally rather than having each card manage its own highlight node.
Add to UIManager.gd:
gdscriptvar _hover_timer: SceneTreeTimer = null
var _hovered_card: Card = null

func on_card_hovered(card: Card):
    if _hover_timer:
        _hover_timer.timeout.disconnect(_on_hover_timeout)
        _hover_timer = null

    if highlighted == card:
        return  # already highlighted, nothing to do

    if highlighted and highlighted != card:
        _clear_card_highlight(highlighted)

    highlighted = card
    _hovered_card = card
    _apply_card_highlight(card)

func on_card_unhovered(card: Card):

    _hover_timer = get_tree().create_timer(delay)
    _hover_timer.timeout.connect(_on_hover_timeout.bind(card))

func _on_hover_timeout(card: Card):

    if highlighted == card and _hovered_card != card:
        _clear_card_highlight(card)
        highlighted = null

func _apply_card_highlight(card: Card):
    card.parts_highlighted = true
    card.z_index = card.card_index + 10
    var tween = card.create_tween()

For the **button hover** problem (moving from card to button would trigger unhover), you have two options:

**Option A — Simpler:** Set `mouse_filter = MOUSE_FILTER_PASS` on the action panel buttons so mouse events pass through to the card's area and the card never technically "unhover".

**Option B — Explicit:** Connect each button's `mouse_entered`/`mouse_exited` to the same `UI_Manager` functions and track a `_button_hovered` flag inside `UI_Manager` alongside `_hovered_card`.

Option A is less code and usually works unless your button sits outside the card's collision area.
